# Dagone — дорожная карта, этап 2

Формат как в этапе 1: ментор объясняет и ревьюит, код и конфиги пишет ученик. Отмечай `[x]`, когда часть пройдена и отревьюена. Закрытый этап: `Roadmap_Stage_1.md`.

Этап 1 оставил рабочего пользователя (регистрация, вход, сессия, смена пароля по письму), каркас Next.js и выкладку на `dagone.ru`. Записей, профилей и людей ещё нет. Главная — заглушка.

Согласовано 2026-11-23.

## Что делаем

Журнал и люди. К концу этапа есть имя Dagone, страница человека, каталог людей, записи трёх уровней доступа, редактор TipTap, дерево комментариев, лайки, друзья без подтверждения, чёрный список и главная со свежими записями и лентой друзей.

Адреса:

- журнал — `dagone.ru/u/{login}`
- запись — `dagone.ru/u/{login}/posts/{id}`
- каталог — `/users`
- настройки — `/settings`

`login` — постоянный адрес и поле в токене. `username` — отображаемое имя, его можно менять, уникальным оно не является. Почта на публичные страницы не попадает.

Поддомен `{login}.dagone.ru` — отдельный модуль после этого этапа. Страница та же, nginx и Next только подменяют хост на `/u/{login}`. Кука уже на домене `dagone.ru`.

## Вне этапа

Сообщества, теги, черновики, картинки внутри записи, визуальные блоки с перетаскиванием, лайки комментариев, уведомления, удаление аккаунта, смена почты и логина, поддомены и wildcard-сертификат, сборка бэкенда в `dist/`, гонка двух вкладок со старым refresh.

Лента друзей — последний модуль. Если этап раздуется, откладываем её, не журнал и не записи.

### 9. Профиль

Первая защищённая запись в API. С неё же закрывается хвост этапа 1: повтор запроса после 401.

- [ ] 9.1 Поля пользователя: `bio` (обычный текст, до 1000 символов, пустое допустимо) и путь аватара. Байты файла в базу не кладём
- [ ] 9.2 `PATCH /users/me`: имя, биография. Логин и почта этим запросом не меняются. Смена пароля — отдельный запрос, старый пароль обязателен, все refresh-сессии кроме текущей отзываются
- [ ] 9.3 Аватар: `multipart`, jpeg/png/webp, лимит размера, файл на диске вне git (правило в `.gitignore`). Чтение — отдельный GET, в публичном ответе только адрес картинки. Замена и удаление
- [ ] 9.4 Публичный ответ человека: `login`, `username`, `bio`, адрес аватара, дата регистрации. Без почты и хеша пароля
- [ ] 9.5 `apiFetch`: ответ 401 → один `refreshTokens()` → повтор того же запроса. Пути `/auth/` не повторяем (там 401 — неверный пароль или токен сброса). Неудачный refresh сообщает стору, что сессии нет. Механизм стора живёт не в `shared`: `shared` не импортирует `entities`
- [ ] 9.6 Страница настроек `/settings`: имя, биография, аватар, смена пароля. Формы на уже существующих `FormCard` и `useFormState`
- [ ] 9.7 Журнал `/u/[login]`: шапка (аватар, имя, логин, биография) и пустое место под записи. Свой журнал отличается ссылкой в настройки. Чужого логина нет — 404. Вёрстка: на широком экране колонка профиля и колонка записей, на узком — друг под другом
- [ ] 9.8 Первая новая миграция: `globalSetup` Playwright приводит `lj_e2e` к схеме один раз перед прогоном. Между тестами базу не чистим. В CI по-прежнему свежий Postgres
- [ ] 9.9 Прод: `client_max_body_size` у nginx для загрузки аватара. Каталог файлов не в репозитории и переживает `git pull`

### 10. Каталог людей

- [ ] 10.1 `GET /users`: постранично (`limit` + `offset`), поиск по логину и имени. Тот же публичный ответ, что в 9.4. Своих блокировок каталог не скрывает — это общий список
- [ ] 10.2 Страница `/users`: поле поиска, карточка ведёт на `/u/{login}`, пустой результат — отдельное состояние, не ошибка

### 11. Редактор и записи

Текст записи и комментария хранится документом TipTap (JSON ProseMirror), не HTML. На экран его рисуют те же расширения, которыми редактировали. Чужие типы узлов на экран не выводятся. `javascript:` в ссылках не допускается.

У записи три уровня. В базе значения английские, на экране русские:

| Значение  | Кто видит                               |
| --------- | --------------------------------------- |
| `public`  | все, включая гостя                      |
| `friends` | автор и те, кого автор добавил в друзья |
| `private` | только автор                            |

Остальным ответ на саму запись — 404. Так по адресу нельзя узнать, что скрытая запись существует. Чёрный список сильнее дружбы: заблокированный не видит `friends`, даже если строка дружбы ещё была.

Списки режутся по тому же правилу:

- журнал гостя и чужого человека — только `public`
- журнал для того, кого автор добавил — `public` и `friends`
- свой журнал — все три
- главная «свежие» (модуль 15) — только `public`
- лента друзей — в модуле 15

- [ ] 11.1 Модель `Post`: автор, заголовок, документ JSON, уровень доступа, даты создания и правки. Удаление автора удаляет его записи
- [ ] 11.2 Редактор в `shared/ui`: TipTap, расширения StarterKit (абзац, выделение, списки, цитата, код, заголовки), Link, Placeholder. Панель комментария без заголовков. Пустой документ не отправляется. Размер JSON ограничен на схеме в `@dagone/shared`
- [ ] 11.3 `POST/PATCH/DELETE` своих записей и `GET` одной. Чужой id править нельзя: проверка автора на сервере. Уровень доступа можно сменить тем же `PATCH`
- [ ] 11.4 Список записей журнала по правилам видимости выше, постранично
- [ ] 11.5 Страницы: новая запись со своего журнала, страница записи, правка своей. Уровень доступа виден автору и выбран до отправки. Интеграционные тесты на матрицу «гость / чужой / друг / автор / заблокированный» для всех трёх уровней

Страницы журнала и записей с ограниченным доступом рендерятся на сервере для текущего зрителя и не кладутся в общий кеш. Публичную запись переводим на ISR с ревалидацией, когда комментарий и правка уже умеют инвалидировать страницу. До этого один серверный путь для всех трёх уровней.

### 12. Дерево комментариев

Комментарий виден ровно тем, кто видит запись. Писать может вошедший человек, который запись видит и которого автор не блокировал. На `private` это только автор.

- [ ] 12.1 Модель `Comment`: запись, автор, необязательный родитель, документ JSON, даты. Родитель обязан быть комментарием той же записи. Глубину сервер не ограничивает и не считает поводом отказать
- [ ] 12.2 Создание, правка своего, удаление своего. Ответ можно написать на любом уровне
- [ ] 12.3 Удаление: лист удаляется. Узел с ответами остаётся, текст заменяется пометкой «комментарий удалён», чтобы ветка не развалилась. Пометку нельзя редактировать
- [ ] 12.4 Выдача — дерево одной записью, по дате среди братьев. Потолок на число комментариев записи (200). Дальше этого потолка — задача следующего этапа, не молчаливая обрезка без сигнала клиенту
- [ ] 12.5 Под записью дерево рисуется отступом, пока колонка текста не становится уже читаемой ширины. Детей следующего уровня на этом экране уже нет: вместо них ссылка «Продолжить ветку». Ссылка открывает ту же запись с этим комментарием как корнем экрана (`?thread=`), отступ снова с нуля, над веткой — ход вверх к родителю и к началу записи. Кнопка ответа есть на каждом комментарии. Редактор — тот же компонент, урезанная панель

### 13. Лайки

- [ ] 13.1 Модель «один лайк на пару человек + запись». Повторное нажатие снимает лайк
- [ ] 13.2 Поставить и снять может тот, кто запись видит. Чужому уровню доступа счётчик не отдаётся (запись и так 404)
- [ ] 13.3 Кнопка на странице записи и в списке журнала: счётчик и состояние «я уже поставил»

### 14. Друзья и чёрный список

Друг — направленная связь. Я добавил человека, он в моём списке чтения. Обратная строка не обязательна. Запроса «принять» нет.

«Для друзей» смотрит в друзей автора, не в тех, кто добавил автора. Я вижу твою запись для друзей, только если ты добавил меня.

- [ ] 14.1 Модели дружбы и блокировки. Нельзя добавить или заблокировать себя. Повторная операция не создаёт вторую строку
- [ ] 14.2 Добавить и убрать друга. Заблокировать и снять блок. Блокировка удаляет обе направленные дружбы этой пары и запрещает добавить снова, пока блок стоит
- [ ] 14.3 Списки: кого я добавил (`/u/{login}/friends` — публичный, как полка журнала) и кого я блокировал (только в настройках)
- [ ] 14.4 На чужом журнале кнопки «в друзья» и «в чёрный список». На заблокированном журнале кнопки дружбы нет. Комментарий заблокированного уже запрещён модулем 12

### 15. Главная

- [ ] 15.1 «Свежие» — `public` всех людей, постранично, новые сверху. Это главная для гостя
- [ ] 15.2 «Лента» для вошедшего — записи людей, которых он добавил. Их `public` видны всегда. Их `friends` видны, только если автор тоже добавил зрителя. `private` не попадают никогда
- [ ] 15.3 Переключатель на главной. Пустая лента объясняет, что друзей пока нет, и ведёт в каталог

## Решения

- Имя в коде — `@dagone/*` и строка Dagone. Каталог сервера и локальные имена баз остаются прежними
- Журнал на пути `/u/{login}`. Поддомен позже подменяет хост на этот путь, модели не меняются. Служебные логины заняты заранее
- Документ TipTap хранится JSON. HTML пользователя в базу не пишем и в разметку целиком не вставляем: рисуем документ своими расширениями
- Картинок в редакторе на этом этапе нет. Аватар — отдельная загрузка файла, не узел документа
- Скрытая запись для лишнего зрителя — 404, и в списке её нет
- Друзья без подтверждения. Уровень `friends` пускает тех, кого добавил автор
- Блокировка рвёт дружбу в обе стороны и перекрывает доступ уровня `friends`. Публичный журнал при блокировке остаётся
- Комментарии — дерево без потолка глубины. Отступ на экране кончается ссылкой «Продолжить ветку»: обсуждение не обрывается, колонка текста не сжимается. Удаление развилки оставляет пометку, лист удаляется
- Журнал и непубличные записи не кешируются общим кешем. ISR публичной записи — после того, как правка и комментарий умеют сбрасывать страницу
- Повтор запроса после 401 делаем в первом защищённом `apiFetch` (модуль 9), не откладываем до записей
