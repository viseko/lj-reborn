Проведи код-ревью. Цель: $ARGUMENTS (если пусто — все незакоммиченные изменения).

1. Посмотри изменения: `git status`, `git diff` (и `git diff --staged`), либо указанный файл/коммит. Сверься с текущим пунктом в `docs/ROADMAP.md`, чтобы понимать, что ученик хотел сделать.
2. Запусти проверки затронутых пакетов: lint, typecheck, test (через `pnpm --filter <пакет> …`). Если что-то падает — это первое замечание, но не чини сам.
3. Оцени по осям: корректность и крайние случаи; безопасность (auth, cookie, валидация, утечки данных в ответах/логах); границы слоёв FSD и публичный API слайсов; соответствие соглашениям из `CLAUDE.md`; тесты (есть ли, проверяют ли поведение); a11y для UI.
4. Ответ:
   - 🔴 / 🟡 / 🟢 — группы по важности, у каждого замечания `файл:строка`, «почему это проблема» и наводящий вопрос или подсказка. Исправленный код не давай.
   - ✅ Что сделано хорошо — конкретно.
   - Вердикт: можно ли отмечать пункт `[x]` (только без 🔴) и что сделать дальше.
5. Если в ревью всплыла повторяющаяся ошибка или пробел — кратко допиши в «Сводку» журнала.
